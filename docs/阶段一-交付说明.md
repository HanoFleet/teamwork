## 3. 本版相对上一版的完善

上一版已经能通过 OpenSpec 校验，但按课程“场景要能逐条判定”的标准还有缺口。本版做了以下修改：

1. **所有场景补 `GIVEN` 前置条件**：143 个场景现在都是“前置条件 / 操作 / 可观测结果”，角色、数据归属和已有数据写清楚；旧版多数场景只有 `WHEN/THEN`。
2. **删除未修改的 MODIFIED 需求**：旧版把“预置核心数据”“密码哈希与会话密钥”“Web 视觉与交互”等未变化条款也放进 delta；本版只保留真正修改的 7 条 `auth-upload` 需求和 5 条 `knowledge-retrieval` 需求，减少合并时的噪声。
3. **去掉重复需求**：旧版 `knowledge-retrieval` 的 ADDED“当前版本原文与异步索引”与 MODIFIED“上传后切分并建立索引”重复；本版合并为一条，并把“状态可观察”场景并入索引需求。
4. **修正自相矛盾的场景**：旧版“更换策略必须显式重建”写“第二次重建前，第一次的旧切片已被删除”，与“先建后换”冲突；本版改为“第二次重建成功后只保留新 generation”。
5. **拆分过长需求**：材料库的编辑、替换、版本历史拆成“在线编辑正文”“版本历史与恢复”“文件替换”三条，每条只陈述一个行为，便于逐条验收。
6. **补放弃的候选方案**：`proposal.md` 增加 7 条被放弃的候选方案；`design.md` 每条取舍都写明放弃了什么、代价由谁承担。
7. **补能力—场景对应表和失败路径覆盖**：新增两张表，`scripts/spec_check.py` 会核对表中数字与实际规约一致。
8. **任务清单可执行化**：从 8 组 30 条扩成 8 组 48 条，第 0 组先确认基线可启动；每条写 `涉及`、`做法`、`verify`，实现者不需要回头猜文件位置或验收命令。
9. **仓库说明面向评审**：`README.md` 把当前阶段、四份文件入口、校验命令、另起会话评审方法和既有底线放在最前面；`AGENTS.md` 增加阶段一约束、场景写法和提交格式。
10. **新增结构自查脚本**：`scripts/spec_check.py` 不依赖 Node，检查四份文件、需求/场景、失败路径、对应表和任务清单；适合教师或组员在没装 OpenSpec CLI 的环境快速核对。
11. **按课程第 3 步补齐八类工程规范**：新增 `docs/standards/01` 至 `08`、`docs/data-dictionary.md`、`.cursor/rules/campusclaw-standards.mdc` 和 `.cursor/skills/campusclaw-engineering/SKILL.md`；安全与评审写进 `AGENTS.md`，每类规范都有“项目事实 / 为什么 / 怎么检查”。
12. **按课程第 4 步补骨架缺口**：在 `platform-foundation` 增加“结构化日志与请求 ID”“存活与就绪检查分离”两条需求，`tasks.md` 增加 1.7/1.8；`/health` 保持不查库的既有契约，依赖状态放到新增的 `/ready`，并在 `05-ops.md` 和 `design.md` 写明这是显式例外。
13. **新增四步核对和规范自查**：`docs/项目启动-四步核对.md` 逐项对照课程完成现象；`scripts/standards_check.py` 检查八类规范、常驻入口、数据字典和 README 链接。

## 5. 评审方式

1. **格式检查**：运行上面三条命令，退出码都应为 0。
2. **人工检查**：另起一个不带历史上下文的会话，只给仓库路径和 `upgrade-material-library`，要求它先读四份文件，再列出含糊或缺失的行为问题。它能按 `tasks.md` 编号实现且问不出业务行为问题，就算通过。
3. **对应关系检查**：打开 `proposal.md` 的 Capability–Scenario Map，逐行核对 capability、需求数、场景数和证据；`spec_check.py` 已自动核对数字。
4. **失败路径检查**：打开 `proposal.md` 的 Failure Path Coverage，确认输入非法、无权限、资源不存在、依赖不可达四类都有具体场景；再在 `specs/` 里抽查对应场景的 `GIVEN/WHEN/THEN`。
5. **规范检查**：运行 `python3 scripts/standards_check.py`；再另起一个会话，只给仓库路径，要求它按 `docs/standards/02-backend.md` 加一个材料标签接口，核对分层、命名、错误码和幂等声明。两次会话结果一致才算规范常驻。
