# 01 产品设计规范（含前端约定）

| 项目 | 内容 |
| --- | --- |
| 规范编号 | `01-product` |
| 掌管范围 | 用户与场景、页面清单、视图状态、术语与文案、表单校验、视觉基线、可达性与响应式 |
| 落地方式 | 常驻约束写入 `.cursor/rules/campusclaw-standards.mdc`；按场景执行的“按规范加一个页面”写成技能 |
| 违反时 | 产品/前端改动不得合并；先改本规范或补页面清单，再改代码 |

## 这一页管什么

管产品形态的一致性：谁在什么场景下看到什么页面、每个视图有哪些状态、文案和术语是否统一、表单什么时候校验、视觉和响应式基线是否被遵守。

不管：接口结构与错误码归 `02-backend.md`；资源访问权限归 `03-security.md`；健康检查与日志字段归 `05-ops.md`。

## 项目事实

- 角色只有 `teacher` 和 `student`，班级来自服务端会话，前端不提供切换班级的入口。
- 当前阶段可用的页面：首页 `/`、材料 `/materials`、材料详情 `/materials/{id}`、编辑 `/materials/{id}/edit`（教师）、版本 `/materials/{id}/versions`（教师）、回收站 `/trash`（教师）、问答 `/ask`、设置 `/settings`。
- 禁用占位：学习路径、作业、练习、通知、班级管理；不注册路由、不请求后端。
- 视觉令牌在 `frontend/src/styles.css`：主色 `--red: #8c1515`，深色主题 `--red: #e15a5a`，背景 `--bg`，卡片 `--paper`，正文 `--ink`，次要文字 `--muted`，分隔线 `--line`。
- 断点统一为 768px。现有样式里的 800px 是待修正偏差，由 `tasks.md` 5.2 改成 768px。
- 现有接口错误体是 `{"error":"<code>"}`；页面按状态码和 `error` 显示文案，不直接显示后端英文枚举。

## 规范条目

| 条目 | 项目事实 | 为什么 | 怎么检查 |
| --- | --- | --- | --- |
| 用户与场景 | 教师：上传、批量上传、看索引状态、编辑/替换、版本、删除/回收站、标签、学情（后续）。学生：浏览、搜索、阅读、提问、进度、收藏。每类场景写到 README 的“用户与场景”节 | 场景不能对应页面，说明页面清单有孤立项 | 逐条场景反查页面；找不到页面即缺陷 |
| 页面清单与信息架构 | 路由清单见“项目事实”；同功能入口唯一；未知路径回到首页或 404，不出现空白页 | 避免同功能多入口和孤立页面 | 按清单逐个访问；出现清单外入口即缺陷 |
| 视图状态完备性 | 每个数据视图必须有四态：加载中（skeleton）、正常、空（含下一步）、错误（401/403/404/409/413/503 可读文案）；上传额外有上传中/索引中/可检索/失败 | 无限加载、无提示空白、只有成功态都会让用户无法判断 | 清空数据看空态；停依赖看错误态；断网看重试 |
| 术语与文案 | 统一用“材料、切片、索引、可检索、版本、回收站、收藏、已读”；错误文案含“发生了什么、可能原因、下一步”，例如“服务暂时不可用，请稍后重试” | 同一概念多种叫法会让用户和测试都失去参照 | 抽查页面文案是否出现术语表外写法；抽查错误是否给出下一步 |
| 表单与校验 | 标题 1 至 255 字；标签 1 至 32 字、每材料最多 10 个；修改说明最多 200 字；单文件不超过 `MAX_UPLOAD_BYTES`；批量最多 20 个、总计 20 MiB。文本在失焦时提示，文件在提交时校验；提交按钮在处理中禁用 | 前端禁用只能防误触，真正去重靠后端幂等 | 逐表单走查；连续点击只产生一次请求；后端仍拒绝重复 |
| 视觉基线 | 间距刻度 4/8/12/16/24/32px；字号 0.72/0.8/0.85/0.9/0.95/1.05/1.25/1.6/2rem；颜色只用 `styles.css` 的 CSS 变量；基础组件：按钮、输入、卡片、标签、提示条、对话框、骨架屏、空状态 | 写死像素和颜色会导致主题和窄屏失控 | 新页面复用现有组件和变量；出现自造颜色或字号即缺陷 |
| 可达性与响应式 | 桌面 ≥768px 左侧导航；窄屏 <768px 底部标签栏；所有交互可键盘到达，焦点可见；表单控件有 label；对比度不低于 4.5:1 | 只做鼠标操作会让键盘用户无法完成主路径 | 只用键盘走登录、列表、详情、编辑；390×844 和 1440×900 各走一次 |
| 状态与流程 | 索引状态 `pending → indexing → ready/failed`；编辑冲突 `409` 显示最新内容和差异；删除后 10 秒内可撤销，回收站可恢复；终结状态（已彻底删除）不可改 | 状态流转不写清，前端会各自发明按钮 | 对终结记录发起修改应被拒绝；两会话同时保存，后者收到 409 且前次结果不被覆盖 |
| 变更可追溯 | 页面或状态变化时同步更新本规范、README 页面清单和 change 的 `proposal.md`/`design.md` | 页面清单和实际不一致，评审无法判断是否漏做 | 变更说明与 README、路由清单对照；未同步即缺陷 |
| 导入导出 | 本 change 不做 CSV 导入；后续加入时：单次最多 200 行，超限整体拒绝；先预览再确认；整批成功才生效；失败给“行号 + 原因”；导出按权限和范围，敏感字段脱敏 | 导入半成功和导出泄露是最常见的教学事故 | 混入非法行应整批拒绝并给行号；导出检查脱敏 |

## 文案模板（最低集合）

- 加载中：骨架屏，不写“加载中…”。
- 空列表：`还没有材料。教师可以上传 PDF、Word 或 PPT；学生可以等教师发布。`
- 空搜索：`没有找到匹配项。试试材料页的标签筛选。`
- 401：`登录已过期，请重新登录。` 登录后回到原页面。
- 403：`当前账号没有这个操作权限。`
- 404：`找不到这份材料，它可能已被删除或不属于本班。`
- 409：`这份材料已被其他人修改，请查看差异后再保存。`
- 413：`文件超过大小上限，请压缩或拆分后重试。`
- 503：`服务暂时不可用，请稍后重试。` 提供重试按钮。
- 索引中：`正在建立索引，稍后即可检索。`
- 索引失败：`索引失败：<原因>。可以重试。`

## 本课最小集合

1. 用户与场景：教师/学生各 3 条主场景。
2. 页面清单与路由：本阶段 8 个可用路由 + 5 个禁用占位。
3. 四态文案模板：加载、空、错误、正常各一组；上传额外四态。
4. 术语表：材料、切片、索引、可检索、版本、回收站、收藏、已读。
5. 视觉基线：间距刻度、字号层级、主色/深色令牌。
6. 响应式：768px 断点，桌面左栏/窄屏底栏。

## 违反时怎么处理

- 页面缺四态或文案含技术错误码：退回前端修改，不进入验收。
- 出现自造颜色、字号或间距：改为复用 `styles.css` 变量和组件。
- 页面清单与实际路由不一致：先更新本规范和 README，再继续实现。
- 例外（例如某个第三方组件无法键盘操作）：把例外、原因和替代检查写进本规范，不做口头豁免。
